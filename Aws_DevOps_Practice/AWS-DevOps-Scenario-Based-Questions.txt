1. **What is the purpose of a NAT gateway, and what are some of its use cases?**
   **Answer:** A NAT (Network Address Translation) gateway enables instances in a private subnet to connect to the internet or other AWS services while preventing inbound internet traffic.  
   **Use Cases:**  
   - Downloading security patches for private EC2 instances.
   - Allowing private instances to send data to external APIs securely.  
   **Real-World Example:** A backend system in a private subnet uses a NAT gateway to download application updates without exposing the subnet to internet traffic.

2. **How do you decide which load balancer is best suited for an application?**
   **Answer:**  
   - **Application Load Balancer (ALB):** Use for HTTP/HTTPS traffic with features like path-based and host-based routing.  
   - **Network Load Balancer (NLB):** Use for high-throughput, low-latency TCP/UDP traffic.  
   - **Classic Load Balancer (CLB):** Use for legacy applications with basic load balancing needs.  
   **Real-World Example:** An e-commerce application uses ALB for routing user requests to microservices, while NLB is used for database traffic requiring low latency.

3. **What are the key features of the Nginx service?**
   **Answer:**  
   - Reverse proxy and load balancing.  
   - HTTP caching.  
   - SSL/TLS termination.  
   - Web server capabilities.  
   **Real-World Example:** Nginx is configured as a reverse proxy to route traffic between a React frontend and a backend Node.js API.

4. **What are the differences between a Network Load Balancer and an Application Load Balancer?**
   **Answer:**  
   - **NLB:** Handles TCP/UDP traffic, supports millions of requests per second, and has ultra-low latency.  
   - **ALB:** Manages HTTP/HTTPS traffic, supports WebSocket, and provides advanced routing based on URL paths or headers.  
   **Real-World Example:** A gaming server uses NLB for real-time multiplayer communication, while a REST API uses ALB for routing requests based on endpoints.

5. **Why is a DynamoDB table used to lock the Terraform state file?**
   **Answer:** DynamoDB is used as a locking mechanism to prevent multiple processes from modifying the state file simultaneously. This ensures consistency and avoids race conditions during deployments.

6. **How can we manage the Terraform state file effectively?**
   **Answer:**  
   - Use remote backends like S3 for centralized state storage.  
   - Enable state locking with DynamoDB to prevent concurrent updates.  
   - Use versioning in S3 to recover from accidental overwrites.  
   **Real-World Example:** A team used an S3 bucket with versioning enabled and a DynamoDB table for locking to manage Terraform states securely.

13. **Write a Dockerfile for a Node.js application, including the build and run commands.**
    **Answer:**  
    ```Dockerfile
    FROM node:16
    WORKDIR /app
    COPY package*.json ./
    RUN npm install
    COPY . .
    EXPOSE 3000
    CMD ["npm", "start"]
    ```
    **Build Command:** `docker build -t node-app .`  
    **Run Command:** `docker run -p 3000:3000 node-app`

14. **Briefly explain Kubernetes architecture, covering each component and its use case.**
    **Answer:**  
    - **Control Plane:** Manages the cluster (API Server, Scheduler, etcd).  
    - **Worker Nodes:** Run application workloads in pods.  
    - **Kubelet:** Communicates with the control plane to manage pods.  
    - **Kube-proxy:** Manages networking within the cluster.  
    **Real-World Example:** Configured a Kubernetes cluster with 3 worker nodes and 1 control plane to run a microservices application.

15. **How do you manage connectivity between multiple pods in a Kubernetes cluster?**
    **Answer:** Use a CNI (Container Network Interface) plugin like Calico or Flannel to establish networking and enable communication between pods.

16. **How do worker nodes communicate with the control plane (master node)?**
    **Answer:** Worker nodes use the kubelet to communicate with the API server in the control plane over HTTPS.

17. **How can we increase the capacity of pods using the CLI (command line interface)?**
    **Answer:** Use the `kubectl scale` command to increase replicas.  
    **Example Command:**  
    ```bash
    kubectl scale deployment <deployment-name> --replicas=<number>
    ```
